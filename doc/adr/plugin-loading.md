# 事务式注册与清单校验时机

代码和配置装配进入同一装载流程。先验证插件描述，再让插件在临时注册器上激活，比较分类型的贡献名称集合，最后由注册表原子提交。配置条目按顺序处理，被禁用的条目直接跳过。

激活、清单或重名错误使当前插件的暂存结果失效。已装入的插件继续可用，后续条目继续处理。注册表不负责读取 JSON 或解析模块路径，加载器也无需枚举可选插件。事务覆盖注册状态，插件自行负责激活期间触发的外部副作用。

配置加载会从已解析模块的位置找到最近的 `package.json`，并在提交前比对包的 `contributes`、运行时声明和暂存注册。构建时随可选插件输出包清单。独立模块没有包清单时，使用运行时声明校验。回归测试用两个连续的插件验证：包声明不符的插件被拒绝，后续插件仍能注册。

模块解析以配置文件为起点，优先采用 Node 的 ESM 条件，包括 `exports.import`。保留 CommonJS 包和省略后缀的相对路径兼容。解析与模块求值分别处理，模块存在但内部依赖缺失时仍报告插件加载失败。
